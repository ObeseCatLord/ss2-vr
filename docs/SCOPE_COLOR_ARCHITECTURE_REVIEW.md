**Selected minimal design, conditional on the gates below.** Retain both ordinary eyes' color/depth and copy their observations plus executed view/projection/depth/viewport before endEye. After both collections have completed and been freed, render each admitted hand's scope with original Render3D into **one reusable texture-backed color target and one scope depth target**. Immediately compose that hand into both retained eyes, then reuse scratch storage for the other hand. Read back completed eyes through the existing bridge; retain its desktop rebuild and pair commit. Bound additional native renders to two per pair. No per-hand retained textures, new IPC images, host layers, command replay, or simulation are needed.

This ordering needs preservation-capable eye depth, with native clears/rebinding audited; merely changing Discard to FALSE proves nothing about later native overwrites. Scratch dimensions/formats initially match the supported native canvas, subject to render-target texture capability checks. Extend existing desktop-alias routing with a scoped render destination; preserve intermediate-target behavior and route binds/copies/readbacks/fills consistently. Do not impersonate an eye index. Scope camera/FOV, root-query identity, local gun/laser/flat-overlay suppression and frozen remote presentation belong to that temporary render purpose. Preserve native scene evaluation and prevent bridge recursion. Native timing, postprocessing history and cleanup isolation remain unproven.

The custom GPU span starts **after** the native scope call, snapshots then-current hardware, binds retained eye targets and draws the lens, then restores identical hardware before any native call. Include targets, depth, viewport/scissor, shaders/constants, samplers/textures, streams/indices and render state, including anything a state block omits.
