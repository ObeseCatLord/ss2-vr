# Scope final-color composition alternative — unreviewed

The existing native prepass/lens-cap proposal still requires loaded-content, destructive-query exclusion, HDR transfer and native cap draw provenance. The following smaller alternative reopens that integration decision; no source implements it.

Verified bridge source: stereo() calls original native Render3D once per eye, checks its final color/depth ownership, calls endEye, then copies pixels. The current scope observations are cleared by endEye; copy them while that exact completed eye is still active. The original invocation has already completed its native collections at this point. Native desktop Render3D is rebuilt after both eyes to restore caches. See bridge.cpp current530..593 and engine.cpp ScopeObservationBank/endEye.

Candidate: observe an ordinary completed eye, render separate native scope views only outside active collections using the same frozen input/native scene, then compose finished scope imagery onto a lens-plane primitive AFTER the ordinary eye's entire Render3D/final effects. This could eliminate an additional native bone query and cap exclusion. It must not insert already-finished scope color inside pre-HDR world rendering.

Preserve native rendering: additional scope views use original Render3D with scoped owner camera/FOV, their own color/depth resources, no simulation/update, no replay of retained commands. Exclude only the local gun in scope-view rendering; native scene/animation/culling/postprocess remain. Use current native ballistic/calibrated aim as optical direction; do not infer ballistic direction from cap geometry. Actual loaded Scope content/full affine still needs admission.

Composition candidate: a tiny GPU lens primitive with projected full affine cap geometry and matching original weapon depth mapping. A GPU state snapshot captured immediately around custom drawing may restore identical cache-entry hardware state only if no native rendering occurs inside that mutation span. This differs from restoring a stale state block around native Render3D, which existing bridge correctly rejects. Both native caches and logical canvas/physical alias routing still need proof. Pixel-only CPU composition is rejected without depth because it could paint over another gun or world occluder.

Required gates before any code: native Render3D final-effect completion and non-nested cleanup; own target/format/viewport and desktop alias routing for scope views; original eye color/depth preservation; actual content geometry and optical plane; scope-view camera/FOV hooks without renderer/transport recursion; GPU sampling/color transfer and depth correctness; restoration matching caches; per-pair/per-hand identity/lifecycle consistency. Finished-color composition is a proposal to remove layers, not proof those gates hold. Scope views can be mono physical telescope images shared by two genuine stereo eyes, but main world rendering remains asymmetric stereo. Performance remains unmeasured.

No native scope callback/image/lens draw is enabled here. Request a bounded Astra architecture decision after the current zoom-causality decision; do not let this record silently replace the approved ordinary scope observation or label optics complete.
