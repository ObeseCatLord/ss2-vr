# Roomscale input policy — Astra disposition

Two effective Astra/xhigh turns locally verified: bounded native investigation,
then senior design review. Read-only/no delegation/runtime. Review result:
conditional GO for submitted-request settlement as a bounded prototype; NO-GO
for production until action duration, conversion and publication ordering are
proved. Main does not promote this policy to the default immersive port.

| Finding | Disposition |
|---|---|
| One native submission is not necessarily one simulation interval | Adopted prerequisite. ProcessPlayerControls/ClientAction store intent at brain144; persistent intent can affect several steps. Prove source cadence, action integration duration and duplicates/zero-multiple steps/pause/network delay for SP/client/listen-server. |
| Void return is not movement acknowledgment | Adopted. Native remote ProcessRPC_t atEE441 can have side effects before unwind; define precise submission/no-retry semantics without another ACK. |
| Submitted-settlement algebra removes attribution | Accepted mathematical statement only: with fixed R and origin O+r, camera delta equals actual anchor delta a. Native acceleration, braking, saturation, airborne/correction break any assumed a=Rr+stick equality. |
| Physical motion can be consumed at walls or saturated stick | Production promotion rejected for the proper6DOF default. Preserve direct one-to-one physical horizontal tracking in free space; conditional prototype acceptance is not behavior equivalence. Walking back after consumed blocked distance can move the virtual body backward. |
| Origin and body-relative packet require one coherent publication | Adopted. Current update builds/sends head/grip packets before publishing its copied Snapshot. A separate settlement could send stale offsets or get overwritten. Reuse original submission/publication; no movement ACK. |
| Older render request can use newer settled origin | Adopted prerequisite. nativeFrameIdentity checks lifecycle, not input sequence. BeginStereo must not combine old HMD input with newer settlement; use bounded settled-sample lower bound/immutable pair snapshot if this policy is ever used. No per-delta generations/history subsystem. |
| Exact local ProcessPlayerControls caller precedes serialization | Adopted for any input-based candidate; restrict local brain/player/handheld walking. Server must not derive a second request from received VR head poses; listen-server injects once. poll/query is not submission. |
| Metre-to-command conversion remains unproved | Adopted blocker. Preserve native basis/scaling/correction/saturation/speed/legged factors, avoid guessed delta/(speed*dt) or copying movement policy. |
| Minimum state | Adopted constraint: existing Snapshot/interval plus last raw sample identity/position, at most one demonstrated in-flight record. No accumulating unaccepted-distance debt or second controller. Lifecycle/recenter/tracking/rider changes establish a fresh baseline. |

No human question is required for correctness gates. User already requires proper
6DOF. This candidate must not silently replace direct horizontal tracking with
speed/acceleration-constrained virtual response. A narrower original native
relative-collision move that returns attributable accepted displacement should
be investigated before considering a different tracking policy; its existence
is unknown, not permission to replace physics or invent an API.

No production roomscale code has been added by this review. Existing HMD/head/
hand tracking and obstruction fade remain; native body-follow collision remains
unfinished. A future bounded proof must connect one raw tracking sample through
the native request, lifecycle/interval, one coherent shared origin/head/hands/
network-pose update, including differing input/simulation rates, interrupted
submission, older render requests, corrections and remote no-double-injection.
Native collision/comfort runtime remains untested under the user's instruction.
