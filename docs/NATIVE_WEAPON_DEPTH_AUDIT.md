# Native weapon depth and optic cap — 2026-10-03

Static-only facts for the fingerprinted Sam2Game/Engine/GfxD3D and owned stock sniper mesh. No viewport/depth changes are implemented by this audit; no runtime was executed.

Base weapon Render0x4C740 receives Matrix34 by value, ret0x30. It constructs its own frustum at0x4C8E3, installs projection, and calls native `_gfxDepthRange(0,0.1)` at0x4C9A4 (return0x4C9A6). The callback is imported via Sam IAT0x294E6C from Engine data export `_gfxDepthRange`0x2E626C, type `void (__cdecl *)(float,float)`. Render resolves model handle+0x24 and calls native mdlRenderModel at0x4C9E3 or0x4CA48. The left-hand branch negates native instance X stretch around that draw and restores it. Projection and saved depth range are restored at0x4CA79/0x4CA91 (return0x4CA93).

The VR weapon-frustum wrapper already substitutes the actual asymmetric XR FOV for owned tracked guns. It does not change the stock0–0.1 depth range. Astra identified why simply injecting a world-depth scope aperture after root Execute can be blocked by the compressed-depth cap; using the stock weapon depth range alone also does not establish physical wall occlusion. Any adjustment must preserve native depth caches, scope to actual owned XR gun rendering, retain desktop/nested passes and restore native state. A device-only viewport override without those proofs is not selected.

The fingerprint-bound stock Scope cap audit identifies rear-plane triangles901 through922 inclusive, contiguous in that surface's928-triangle native index list. That suggests a narrowly identified native draw could omit only the cap without replacing shared materials or extracting the gun model. Actual draw identity/offset/primitive layout, loaded resource compatibility, UV/material lens meaning and native insertion/color stage remain required bindings; no split draw or cap removal is implemented. Candidate UV bounds were examined only in private scratch and are not treated as verified optical semantics.

Main additionally verified GfxD3D startup4A0F/4A14 binds the imported callback data to native56A0. This cdecl(float,float) callback clamps bounds, compares/writes the engine depth-range cache through IATC0E8/C0E4, then reads/modifies/submits D3D9 viewport via vslots48 and47 at5772/5790. Hooking the native callback before it executes would preserve those caches/profiling; overriding only the physical device would bypass them. No callback hook is implemented here.

Depth comparability also requires matching projection near/far, not just removing0–0.1 compression. Native weapon mthFrustumFOVX caller4C8D4..4C8E3 pushes far10000 and the resource near value+6C, while the current VR wrapper retains those native near/far arguments. Native world projection can differ. A physical optic/gun-depth adapter must freeze the world's actual near/far and matching XR FOV for its depth-tested draw, restore native depth state and preserve desktop/nested passes. Full view/projection correspondence is still a design gate; changing viewport bounds alone is not selected.
